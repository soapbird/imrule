`skills/README.md` §5.10을 따른다. 수준: **필수**는 어기면 제출하지 않는다, **권장**은 가능하면 지킨다.

| ID | 수준 | 규칙 | 근거 |
|---|---|---|---|

## 2. 비공개 정보 제거 (공개 저장소)

| ID | 수준 | 대상 | 처리 |
|---|---|---|---|
| ISSUE-P01 | 필수 | 토큰·API 키·비밀번호·개인 키 (`ghp_…`, `sk-…`, `xox…`, `AKIA…`, JWT, PEM) | `<redacted>` |
| ISSUE-P02 | 필수 | `Authorization`·쿠키 헤더, MCP `headers`·`env` 값, `.env` 내용 | `<redacted>` — 키 이름은 남겨도 됨 |
| ISSUE-P03 | 필수 | URL의 `user:pass@`, 쿼리의 `token=`·`key=`·`sig=` 등 | `<redacted>` |
| ISSUE-P04 | 필수 | 홈 디렉터리 경로, 사용자 이름 | `~`, `<user>` |
| ISSUE-P05 | 필수 | 비공개 프로젝트 이름·경로 | `<project>` — 사용자가 공개를 허락한 경우만 원문 |
| ISSUE-P06 | 필수 | 사내 호스트·IP·레지스트리 주소·내부 URL, 비공개 저장소 주소 | `<host>`, `<registry>`, `<private-repo>` |
| ISSUE-P07 | 필수 | 소스 코드·문서 원문 | 문제를 보이는 최소 예시로 새로 쓴다 |

- `collect.py`가 P01~P05를 1차로 가린다(`redactions`에 건수). P06·P07과 사용자가 붙여 넣은 출력은 스크립트를 거치지 않으므로 **에이전트가 직접** 가린다.
- 가린 것을 초안 머리에 "가린 정보: 자동 n건 + 직접 n건(무엇)"으로 적는다.
- 판단이 서지 않으면 가리고, 원문 공개 여부를 사용자에게 묻는다.

## 3. 제출

| ID | 수준 | 규칙 | 근거 |
|---|---|---|---|
| ISSUE-S01 | 필수 | 제목·라벨·본문 **전체**를 보여주고 명시적 승인 후에만 `gh issue create`/`gh issue comment` | 공개 저장소에 대한 외부 공개 행위 (§5.10) |
| ISSUE-S02 | 필수 | 승인 후 내용이 바뀌면 다시 승인받는다 | 승인한 것과 올라간 것이 같아야 한다 |
| ISSUE-S03 | 필수 | 제출 전 중복 검색(`--state all`). 열린 중복이 있으면 댓글 초안으로 전환 | 이슈 분산 방지 (§5.10) |
| ISSUE-S04 | 필수 | `--run`은 읽기 전용이거나 `--dry-run`인 명령만. `init`·`mcp auth`·설치 명령은 실행하지 않는다 | 진단이 사용자 프로젝트를 바꾸면 안 된다 |
| ISSUE-S05 | 필수 | 보안 취약점은 공개 이슈로 올리지 않고 `SECURITY.md` 절차를 안내 | 공개 전 수정 기회 |
| ISSUE-S06 | 권장 | 본문 임시 파일은 저장소 밖에 만들고 제출 후 지운다 | 실수로 커밋되지 않게 |
| ISSUE-S07 | 권장 | gh를 못 쓰면 제목·라벨만 넣은 새 이슈 링크 + 본문 파일로 안내 | 본문을 URL에 넣으면 길이 제한·기록 노출 |
