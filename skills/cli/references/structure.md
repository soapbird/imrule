## 1. 명령 구조

- 도구 이름은 프로젝트 이름과 같게 한다 (`imrule`, `imnovel`). 짧은 별칭이 필요하면 README에 명시한다.
- 하위 명령은 한 가지 방식으로 통일한다.
  - 동사형: `imrule apply`, `imrule clear`
  - 명사 + 동사형: `imrule skills add`, `imrule mcp remove`
  - 한 도구 안에서 두 방식을 섞을 때는 "명사 그룹 아래 동사" 규칙을 지킨다 (`skills add`는 되고 `add-skill`은 안 됨).
- 인자 없이 실행하면 도움말을 보여준다 (파서의 "인자 필수" 옵션). 기본 동작이 파일을 바꾸면 안 된다.
- 자주 쓰는 하위 명령에는 짧은 별칭을 둘 수 있다 (`update` → `up`, `list` → `ls`). 도움말에 표시한다.

## 2. 전역 옵션

| 옵션 | 뜻 | 비고 |
|---|---|---|
| `-h`, `--help` | 도움말을 stdout에 출력, 종료 코드 0 | 첫 줄에 한 줄 설명, 예시를 포함 |
| `--version` | 버전을 stdout에 출력, 종료 코드 0 | `<도구> <VERSION>` 형식. VERSION 파일·패키지 메타데이터에서 읽음 |
| `-v`, `--verbose` | 로그 레벨 올리기 (반복 가능) | 로그는 stderr |
| `-q`, `--quiet` | 결과 외 출력 억제 | |
| `--json` | 결과를 JSON 문서 하나로 stdout에 | 스트림이면 JSONL. 사람용 출력과 섞지 않음 |
| `--no-color` | 색 끄기 | `NO_COLOR` 환경 변수와 같은 효과 |
| `-n`, `--dry-run` | 바꿀 내용만 보고 | 파일·원격 상태를 바꾸는 명령에 필수 |
| `-y`, `--yes` | 확인 프롬프트 생략 | TTY가 아니면 프롬프트 대신 에러(종료 코드 2) |
| `--project-root DIR` | 작업 대상 디렉터리 | 프로젝트 파일을 다루는 도구 |

- 비밀값(토큰·비밀번호)을 옵션 값으로 받지 않는다. 쉘 히스토리와 `ps`에 남는다. 대신 환경 변수, `--token-file PATH`, stdin(`--token-stdin`)을 쓴다.
- 옵션 이름은 kebab-case (`--dry-run`), 값 목록은 소문자 (`--format json`).

## 3. 출력 채널

| 내용 | 채널 |
|---|---|
| 명령의 결과 데이터 (목록, 생성된 경로, JSON) | stdout |
| 진행 상황, 로그, 경고, 에러 메시지, 프롬프트 | stderr |
| `--help`, `--version` | stdout |

- 결과를 쓰는 코드는 한 모듈(`output`)에 모은다. 다른 모듈은 값을 반환만 한다.
- 파이프가 닫혀도(`| head`) 에러로 죽지 않는다 (BrokenPipe를 정상 종료로 처리).
- 색·스피너·진행 막대는 stdout/stderr가 TTY일 때만, `NO_COLOR`가 설정되지 않았을 때만.
- 에러 메시지는 `error: <무엇이 잘못됐는지>` 한 줄 + 필요하면 `hint: <어떻게 고치는지>` 한 줄. 스택 트레이스는 `-v` 또는 디버그 모드에서만.

## 4. 종료 코드

| 코드 | 뜻 | 예 |
|---|---|---|
| 0 | 성공 | |
| 1 | 실행 실패 (도메인 에러, I/O 실패) | 설정 파일 파싱 실패 |
| 2 | 사용법 오류 | 없는 옵션, 필수 인자 누락, TTY 없이 확인 필요 |
| 130 | 사용자 중단 (Ctrl-C) | |
| 3~ | 도구 고유 코드 | 문서화한 경우만 (예: 3 = 결과 없음) |

- 에러 → 종료 코드 매핑은 최상위 한 곳(엔트리 함수)에서만 한다. 깊은 곳에서 프로세스를 종료하지 않는다.
- 도구 고유 코드를 쓰면 README "종료 코드" 표에 적는다.

## 5. 설정과 환경 변수

우선순위 (위가 이긴다):

1. 명령행 플래그
2. 환경 변수 `<PROJECT>_*`
3. 프로젝트 설정 파일 (예: `.<app>/config.toml`, `<app>.toml`)
4. 사용자 설정 파일 `$XDG_CONFIG_HOME/<app>/config.toml` (없으면 `~/.config/<app>/config.toml`)
5. 기본값

- macOS에서도 사용자 설정은 `~/.config/<app>/`이다. `~/Library/Application Support`로 가는 API(`dirs::config_dir`, `platformdirs.user_config_dir`)를 그대로 쓰지 않는다.
- 환경 변수 이름은 `<PROJECT>_<키>` 대문자 snake_case (`IMRULE_CONFIG`, `IMNOVEL_DATABASE`). 표준 변수(`HOME`, `NO_COLOR`, `XDG_*`, `CI` 등)와 외부 SDK가 정한 변수(`OPENAI_API_KEY` 등)는 예외다. 우리 도구가 새로 정의하는 변수는 모두 접두사를 붙인다.
- `.env` 파일을 읽는다면 실제 환경 변수를 덮어쓰지 않는다.
